the diamond

keyed to experimentation

Before it ships, it is a choice

Once it has launched, can you randomize? is a fact about the past. Asked early, it is a design decision you still own:

  • hold out a slice of users
  • stagger the rollout by market or by cohort
  • randomise the prompt, not the feature

the platform

keyed to experimentation

Two checklists, and a platform that runs them for you

On a mature team almost none of this is a matter of remembering. You file an experiment the way you file a pull request: the metric comes from a registry rather than a text box, the detectable effect is filled in from the prior store for that metric, guardrails attach themselves, and randomisation, the ratio check, variance reduction and the sequential test are defaults you would have to work to switch off. Where the platform does not do it for you, these are the lists you run by hand.

before it starts · no plan, no flag
  • the metric comes from the registry, not from a text box
  • the MDE comes from the prior store, not from what would be nice
  • guardrails attached up front: crashes, latency, refunds
  • behind a flag, logging exposure rather than eligibility
  • one live test per surface, in its own layer
  • switchback or clusters if treating one unit touches another
  • the decision rule written before launch, not after the readout
before you believe it
  • sample ratio check: did randomisation actually hold?
  • exposure counts: did the variant reach anyone at all?
  • sequential or always-valid, so the day-three peek was licensed
  • guardrails read before the primary metric
  • the segment you pre-registered, not the eleven on offer
  • CUPED against the pre-period, before you ask for more traffic
  • the estimate shrunk toward the prior, because raw winners are inflated

Nothing reaches every user without a link back to the experiment that justified it. That one rule is what keeps the theory layer complete, because it makes the write-up a condition of shipping rather than an act of virtue.

The gate is not step one, it is the floor under all four exits. If the metric is wrong, every box above it is wrong quietly.

The lookup is not step one either, it is the ceiling over all four. A question the theory layer has already answered does not need an exit, and one it half-answers enters with a prior instead of a blank page.

No mechanism, no test. No exposure log, no effect. The first rule kills the questions that were never going to teach anything; the second kills the answers that were never going to be true.
